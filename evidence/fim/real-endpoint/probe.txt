## 3) Protocol probes against every candidate listener

< Connection: close
< Proxy-Connection: close
< Content-Length: 0
$ curl --http2-prior-knowledge …   -> peer sends non-HTTP/2 data

## 4) Endpoint shapes vd-fim can speak (for a future real endpoint)
vd-fim (crates/vd-fim) has exactly two protocols:
  - OpenAiFim:  POST <base>/v1/completions  {"prompt":…, "suffix":…}
  - LlamaCpp:   POST <base>/infill          {"input_prefix":…, "input_suffix":…}
No discovered listener implements either shape.

## 5) Conclusion
No local DSH-exposed OpenAI-compatible `/v1/completions` or llama.cpp `/infill`
endpoint exists in this environment, so AC-14 cannot be moved from MANUAL to an
automated positive-path proof on this machine. The degradation path (dead
endpoint -> short Failed reason) is automatable and is covered by the existing
vd-fim unit/integration tests; the positive and cancellation-with-late-reply
cases need a real endpoint of one of the two shapes above.

This is a local harness environment probe, not a public service; it makes no
claim about any provider's FIM compatibility.
