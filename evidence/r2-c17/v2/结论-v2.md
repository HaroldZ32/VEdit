## 0. 变更点（相对 v1，结论不变）

1. **整窗 grab 的绝对 p50 跨会话不可复现**：同一官方镜像背靠背两次复跑，plain 基线
   1506.53 → 1616.26 µs、Verilog 基线 2049.95 → 1771.83 µs；v1 的 1385 / 1878.81 与它们的差距
   （plain 比 v2A 低 8.0%；Verilog 落在两次 v2 之间）与这一散布同量级。
   → v1 §5 的绝对数字只能当量级，不能当验收阈值或回归基线。
2. **注入 p50 比 v1 略高**（v2A +1.9%–13.6%，v2B +3.7%–9.5%；同镜像散布 1.7%–7.2%），
   方向略偏慢但幅度在噪声带内；最差 p95 仍只有帧预算的 **0.74%**，「可以增量」不变。
3. **两张镜像的被测栈逐字节相同**（KTextEditor/KSyntaxHighlighting 公共头与 `.so`、
   Mesa 26.0.8、glibc 2.43、Qt 6.10.2），所以 v1↔v2 的数字差异**不可能来自镜像内容**，
   只能来自宿主负载/调度（v1 未记录宿主 load；v2 记录了 load(1m/5m/15m)=4.83/5.21/4.16，16 核）。
4. **所有确定性/像素级结论逐位一致**（1024 上限、`setDefaultStyle`、语义色、20/20 CHECK PASS）。

且满足全部前置：

| 同一套探针脚本（未修改） | `run-probe.sh` sha256 前后一致；探针在官方镜像内**重新编译**（v1 构建树先删除） | `16-…`、`01-build.log` |

而是接口自身的三条硬约束（见 §2）。

## 2. 官方镜像上复现的三条硬约束（C16/A1g/A1h 的设计输入）

1. **每行属性 range 上限 1024**：1000 range/行 → 标记像素 `103568`；1100 range/行 → `0`
   （整行属性被静默丢弃，不报错）。证据：`v2/02-run.log:56-59`（与 v1 行号相同）。
   → R2 的 overlay 必须按行合并或保证单行 <1024（超长行/压缩文件是风险点）。
2. **无文档级 range 枚举、无逐点属性查询、无公共语义高亮 API**：官方镜像内重做阴性查证
   `grep -rn movingRanges|attributesAt`、`grep -rni semantic` → 全部 `[exit=1]` 无匹配；
   同方法正对照 `newMovingRange` → `document.h:1489 [exit=0]`。证据：`v2/19-negative-api.txt`。
   → **A1g 的「逐 range 单一 owner」必须在应用侧用 owner 注册表实现**，不能向编辑器查询。
3. **语义样式需应用侧解析主题**：`Attribute::setDefaultStyle()` 在默认内建主题下
   **可查询但不参与渲染**（文字带饱和像素 `347 → 347`）；应用侧用
   `Theme::textColor(TextStyle)` 解析后显式设色则生效（87 个精确同色像素，
   `CHECK semantic.theme_resolved_colors.range PASS`）。证据：`v2/02-run.log:46-53`。
   → 语义着色落点是「应用侧 语义类 → 主题色 → 显式 Attribute」，不是编辑器的语义 API。

**A1h 仍然成立**：删除全部 overlay range 后同一行带回到 `30` 个底色关键字像素、
0 个 overlay 前景像素（`CHECK overlay.removal.restores.base.foreground PASS`），
底座着色不依赖 overlay 的存在。

## 3. 性能判定：**可以增量**（官方镜像复跑）

平均 62 行视口、120,001 行文档、200 帧（Verilog 120 帧）滚动，注入成本（p50 / p95，µs）：

| 策略 | plain | Verilog |
|---|---|---|
| 全量重建 / 行 | 18.621 / 29.016 | 19.888 / 27.9795 |
| 全量重建 / token | 68.111 / 102.131 | 83.0195 / 122.398 |
| 增量池（只增删进出视口的行） | 9.2875 / 19.053 | 7.429 / 16.6875 |

（v2A；v2B 见 `20-compare-v1-v2.md` §4。）

- 最差 p95 **122.853 µs**（v2B plain per-token）= 16.7 ms 帧预算的 **0.74%**；
  最差单帧 max **149.647 µs** = **0.90%**。结论与 v1 一致：注入不是瓶颈，增量池最优。
- 整窗离屏渲染仍是主成本（1.5–2.9 ms 量级）；overlay 追加约 +0.2–1.0 ms（+12%–59%，噪声很大）。
  **grab 的绝对值不得作为阈值**（同镜像两次就差 7%–14%）。

## 4. 适用范围与未证明（不得外推）

- 本结论成立于 **官方构建镜像**：Ubuntu 26.04.1 / Qt 6.10.2 / KF6 6.24.0（KTextEditor +
  KSyntaxHighlighting）/ tree-sitter 0.25.9 / glibc 2.43 / Mesa 26.0.8（llvmpipe）。
  该镜像是**构建镜像**，不是交付的 AppImage 运行形态；交付包内 Qt/KF6 的
  运行期行为由 T11（私有运行时）与 T12（双宿主矩阵）负责，本任务未覆盖。
- `setDefaultStyle` 只在**默认内建主题**（空 HOME）下测过；具名主题/用户配色未测。
- zDepth 优先级仍是源码推断，未做像素级对照。
- `grab()` 是整窗离屏渲染，不等于屏上局部重绘成本；4K/HiDPI/多视图/字体切换未测。
- 1024 上限只在 plain 模式逐点枚举；有底座高亮时的合并列表上限未单独枚举。

## 5. 对 C16/C17/A1g/A1h 的落点（与 v1 相同，v2 未推翻）

- **C17**：宿主侧接口存在且可用；overlay 落地点确定。
- **C16/A1g**：单一 owner 的仲裁点在**应用侧**（`OverlayRegistry` 一类），渲染层已验证
  overlay 覆盖底色；验收判据应是「同一 range 只创建一次 + 开关 overlay 的像素差」，
  不是「向编辑器查询属性」。
- **A1h**：关闭 overlay 即回退底座颜色，无崩溃。
