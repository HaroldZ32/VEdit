# Git and Subversion through the host shell

The shared Rust host launch code applies process variables, restored host PATH, and the imported global and project overlay. It removes AppDir directories from PATH and rejects AppDir executables, including symlink targets. It strips `LD_LIBRARY_PATH` and `LOCPATH` from the launch environment. Git and SVN search effective PATH before the named fallback variables. Job-specific credential environment entries are applied per process. PTY-specific terminal capability variables are added by the terminal.

VCS jobs and version probes use the saved shell in noninteractive mode. The shell receives the executable and command arguments as separate values. csh and tcsh use a fixed `/bin/sh` trampoline to preserve empty arguments. Interactive PTY startup continues to use the native shell startup behavior.

## Review repair: effective execute access

- `cargo +stable test --offline --locked -p vd-vcs --test toolchain skips_candidates_without_execute_access_for_the_current_user -- --nocapture` reproduced the shadowing bug under UID 1000 before the resolver change. Attempting to execute the first file returned Permission Denied, but the resolver selected it, so the test exited 101. After the change all four toolchain tests passed under UID 1000 and independently as `nobody` in the pinned CentOS 7 image. [CentOS unprivileged regression log](execute-access-centos-user.log)
- `strace -f -e trace=faccessat2,faccessat -e inject=faccessat2:error=ENOSYS …/toolchain-8607fd3bdb90d9f4 skips_candidates_without_execute_access_for_the_current_user --nocapture` simulated an older kernel. The trace showed `faccessat` deny the inaccessible candidate and accept the fallback. The regression exited 0. The older-kernel fallback applies when the process's real and effective UID and GID match, as they do in a normal VEdit launch. [Syscall fallback log](execute-access-fallback.log)
- A separate resolver probe built in the pinned CentOS 7 image ran as `nobody` against root-owned candidates. It skipped an owner-only `0744` executable, honored an ACL that denied the first candidate and granted the second, and accepted a `0750` candidate owned by the user's group. All three cases exited 0. [Ownership, group and ACL log](execute-access-user-acl.log)
- Pinned `cargo test --offline --locked -p vd-vcs` passed 86 tests. Scoped strict Clippy, `cargo fmt -p vd-vcs -- --check`, and `cargo build --offline --locked -p vd-ffi` all exited 0. [Pinned build and test log](execute-access-pinned-gates.log)

The unfiltered Rust FFI run encountered a language-tool-missing assertion before edits (`deeplint::tests::a_missing_slang_binary_fails_the_elaboration_with_its_tool_name`, 86 passed and 1 failed, exit 101). The unfiltered ABI integration test later reached 20 passed and 1 failed at its corresponding `deeplint_reports_a_missing_binary_as_a_typed_failure` assertion. The VCS and environment selections above ran independently. The pinned local toolchain lacks Miri, and these process-spawning checks run against native binaries. The native shell matrix covers the tools installed in the container. Remote network transports and other shell families were outside this matrix.
