## Boundaries

* **`worktree remove` is not implemented in this batch.** `worktree`/`stash`/`submodule` stay OUT of the write allow-list (asserted: the gate refuses them);
  batch 5b owns them. When they land, `worktree remove` must use the same
  `confirmTwice` helper; the AC-5.3 item cannot be verified here because the
  operation does not exist yet — this is stated rather than claimed.
* **`merge` continuation uses `git commit --no-edit`** because the delivery
  baseline (git 1.8.3.1) has no `merge --continue`; rebase/cherry-pick/revert use
  their `--continue` (all present on 1.8.3.1, verified in the pinned image).
* **`clean` never removes directories** (`-d` is never passed) and only the given
  paths; `-x`/`-X` are not offered.
* **The conflict resolution entry is the existing Stage action** (stage the
  resolved file, then Continue). A 3-way merge editor is out of scope.
* **Double confirmation is a UI policy** (`confirmTwice` + the provider seam);
  the backend does not enforce it, exactly as documented for batch 3b's
  single confirmations. Headless with no provider, the confirmation is refused
  (nothing is written), which is what the "zero write" checks observe.
* **A rebase conflict is aborted in the Rust E2E, continued in no test**: the
  continue path is the same command as merge's (`rebase --continue`) and is
  covered by `the_no_edit_flags_are_present_so_no_editor_blocks` argv assertion;
  a resolved-rebase *continue* end-to-end is not exercised.
