# Realtime Outline boundary checks

The offscreen Qt fixture tested `6744f231` using the production application shell, project and module-tree integrations, diagnostics library, vendored Tree-sitter grammar, and real Slang and slang-server. It linked these existing Release archives using the `vedit-realtime-context-e2e` Ninja link command with a scratch `main()` and scratch output paths. The published build was mounted read-only in `vedit-qt6-build:local` with networking disabled. The repository's unchanged `vedit-realtime-context-e2e` also passed when run directly with the same Slang tools.

- The named catalog top `driver` directly instantiated 66 modules `a00`–`a65` and a clean `cap.sv` tab. In `cap.sv`, `z_real` was an elaborated child and all 66 inferred candidates were under `if (0)`. The options available to the selector exceeded 64. The active file, the catalog child `z_real.sv`, and `a00.sv`–`a61.sv` made up the exact 64-file Slang session. Truncation was reported and `a62.sv`–`a65.sv` were omitted.
- `driver` instantiated `forms #(.ENABLE(0))`, so the catalog had no outgoing edges for `forms.sv`, while `driver` independently made the three target definitions known. The clean `forms.sv` tab used `ENABLE=1` and contained `param_child #(.WIDTH(2)) u_param (...)`, `multi_child u_first (...), u_second (...)`, `\escaped.child u_escaped (...)`, and `genuinely_missing u_missing ()`. The real grammar found 1, 2, 1 and 1 sites respectively. The first three names matched actual Slang owner entries. Outline showed all four intentional bad-port errors and one unknown-module error for `genuinely_missing`.

The helper follow-up reproduced two additional issues against the original header. Downstream deletion of the shadowed tab left its inferred child in the session. Three disjoint 64-file closures omitted the last active closure, so the controller's append fallback would yield 129 operands. The corrected helper filters ineligible tabs before their closure is consulted, filters shadowed children before consuming the per-file budget, and fills the session from the active closure first. The final sort keeps the full union stable as focus changes when it fits.

The red and green scratch runs used `c++ -std=c++20 -Wall -Wextra -Wpedantic -Werror` and Qt6Core against the production header in the same container. The red variant used the old helper signature and downstream shadow subtraction. The permanent cases in `diagnostics_selftest.cpp` run the production controller with a recording LSP backend and verify exact operand order and session reuse at 128 files. The selftest was rebuilt using its original Ninja compile and link flags, with output files redirected to scratch. The full watcher rebuild and runtime gates are covered separately.
