# r2-c15-probe 结论：SyntaxProvider 接缝 + 编译期 grammar 选择 + 运行期开关

**结论：接缝真实可换（proven）。**第二个 grammar（tree-sitter-json，MIT，锁 commit）
接进同一接口，两次构建的**全部源码 sha256 完全一致**，唯一变化是 CMake 配置项
`-DSEAM_GRAMMAR=`；运行期 `--tree-sitter=off` 与 `-DSEAM_TREESITTER=OFF` 两种关闭方式
都能构建并正常启动。C15 的“编译期可选择 grammar、运行期可整体关闭 tree-sitter、
不把具体 grammar 硬编码进架构”在探针层面成立。

## 2. (a) 抽象 SyntaxProvider：五类能力，接口无 grammar 类型

`probes/c15-seam/src/syntax_provider.hpp`（唯一供调用方使用的头文件）：

| 能力 | 接口 |
|---|---|
| parse | `ParseTreePtr parse(std::string_view)`；`ParseTree` 是**前置声明的不透明句柄**，实现在 .cpp 内 |
| query | `queryIds()` + `queryMatchCount(tree, query_id)`（逻辑 query 名，如 `"highlights"`） |
| highlight spans | `std::vector<HighlightSpan> highlightSpans(tree)` |
| fold ranges | `std::vector<FoldRegion> foldRegions(tree)` |
| structure | `std::vector<StructureNode> structure(tree)` |

接口泄漏检查（证据 `00-pins.txt`，必须为空）：

```text
$ grep -nE 'TS[A-Z][A-Za-z]*|tree_sitter|node_type|TSTree|TSNode|TSQuery' src/syntax_provider.hpp src/main.cpp
  no grammar type appears in the interface or the caller
```

同一命令证明了**调用方**（`src/main.cpp`）也不含任何 grammar 类型——它只调用抽象接口。
grammar 的节点/query 文本只出现在 registry 生成的构建头里（`grammar_config_generated.hpp`，
由 CMake 从所选 grammar 的 `queries/*.scm` 生成），不进入接口，也不进入调用方。

## 3. (b) 编译期选择 grammar（CMake option），并接了两个 grammar

| | Verilog 系（占位） | 非 Verilog（真实上游） |
|---|---|---|
| id | `verilog_placeholder` | `json` |
| 来源 | 本仓自写 `grammars/verilog_placeholder/grammar.js`，tree-sitter CLI 0.27.1 生成 | 上游 `tree-sitter/tree-sitter-json`，锁 commit `254c42a6476413b776221e03982ac8ae159eeb72` |
| 许可 | MIT（自写，见 `LICENSE`/`PROVENANCE.md`） | MIT（`LICENSE`，Copyright 2014 Max Brunsfeld）——**未绑定任何 GPL grammar** |
| parser.c sha256 | `afcef39bb867396dc550e82adb33e3a4bce239208a6960900f03ec5532263386` | `9a266ae4a0305b8a2769bee90a14ac06914bdc83a509f16428311eac2845637e` |
| 选中方式 | `-DSEAM_GRAMMAR=verilog_placeholder` | `-DSEAM_GRAMMAR=json` |

CMake 里只有一段 `if(SEAM_GRAMMAR STREQUAL ...)` 的映射（目录、符号名、版本串），
生成 `grammar_config_generated.hpp`；`src/grammar_registry.cpp` 只是把生成头的值装进
`GrammarSlot`，源码不带任何 grammar 名。

## 4. (d) “换第二个 grammar 只改配置/注册表、不改接口与调用方”——diff 证据

`04-swap-proof.txt`：

```text
== diff of source manifests between the two grammar builds ==
IDENTICAL: every source file hashed the same before/after the grammar switch
[diff exit=0]

== CMake cache: the only configured difference ==
-SEAM_GRAMMAR:STRING=verilog_placeholder
+SEAM_GRAMMAR:STRING=json
 SEAM_TREESITTER:BOOL=ON
 SEAM_TS_LINK:STRING=shared
```

两次构建树里不同的只有构建产物（`CMakeCache.txt`、生成头、`libgrammar_*.a`、可执行文件、
ninja 中间文件）——没有任何 `src/`、`grammars/`、`third_party/` 源文件变化。

实际链接进二进制的 grammar 符号（`05-grammar-manifest.txt`，`nm` 观测）：

```text
-- build/verilog --   tree_sitter_verilog_placeholder
-- build/json --      tree_sitter_json
```

两次运行的五能力输出（`02-run-both-grammars.txt`）：

| 构建 | PROVIDER | HIGHLIGHT_SPANS | FOLD_REGIONS | STRUCTURE_ITEMS | RESULT |
|---|---|---|---|---|---|
| A（verilog） | `verilog_placeholder (minimal Verilog-family grammar)` | 52 | 3 | 2 | PASS / exit 0 |
| B（json） | `tree-sitter-json` | 21 | 1 | 7 | PASS / exit 0 |

（`SPAN[0] line=0 bytes=0-49 capture=comment`、`FOLD[0] lines=1-9 kind=fold`、
`STRUCT[0] line=1 kind=item name=counter` 等逐项输出见原日志。）

## 5. (c) 运行期整体关闭 tree-sitter 后仍可构建启动

1. **运行期关闭**（同一二进制）：`--tree-sitter=off` → `PROVIDER=disabled`、
   `CAPABILITIES parse=0 query=0 highlight=0 fold=0 structure=0`、`parse` 返回 null、
   五类结果为空、`RESULT=PASS failures=0`、退出码 0（`03-runtime-switch.txt`）。
   调用方一行未改：关闭只是选择了 `makeDisabledProvider()`。
2. **编译期关闭**：`-DSEAM_TREESITTER=OFF` 的构建不编译 `tree_sitter_provider.cpp`、
   不链 grammar、不链 libtree-sitter，仍能构建并启动（同样输出 disabled 五能力）。
   该配置用于证明“整条 tree-sitter 依赖可以在构建层摘掉”。

## 6. (e) 链接方式 + C18 私有运行时的可替换性

| 方式 | 观测 | 证据 |
|---|---|---|
| shared（默认） | `ldd` 出现 `libtree-sitter.so.0.25 => /usr/lib/x86_64-linux-gnu/libtree-sitter.so.0.25`；`readelf -d` NEEDED `libtree-sitter.so.0.25` | `06-link-mode.txt` |
| static | `ldd` 无 tree-sitter 行；`readelf -d` 无该 NEEDED；`libtree-sitter.a` 整体链入，运行 `RESULT=PASS` | `06-link-mode.txt` |
| grammar 库 | 两种链接方式下 grammar 始终静态链入（`nm` 只出现被选中的 `tree_sitter_<id>` 符号） | `05-grammar-manifest.txt` |

**C18 结论：**私有运行时可以二选一——
- 动态：把 `libtree-sitter.so.0.25` 随包放进 `AppDir/usr/lib`（RPATH `$ORIGIN/../lib`），
  grammar 静态编译进主二进制；
- 静态：`libtree-sitter.a` 直接链入，二进制无外部依赖，同时 grammar 也静态。
**可替换性不依赖运行期动态加载 grammar**：C15 的“可换”发生在**编译期配置层**——
换 grammar = 改 `SEAM_GRAMMAR` 重新编译；registry 由配置生成，接口/调用方零改动。
即使全部静态编译，探测到的替换路径（cmake option + 生成头）仍然成立；
这与运行期“整体关闭 tree-sitter”是两条独立开关，互不依赖。

## 7. 与 requirements / R2 验收的关系

- **C15**：接缝真实可换，已由“两次构建 + 源码 hash 一致 + 运行期/编译期关断”实证。
- **C18**：tree-sitter 运行库可随包（动态）或静态链入；静态编译不破坏编译期可替换性。
- **A1h（运行期关闭 tree-sitter 回退 KSyntaxHighlighting）**：本探针只验证了 provider 层
  的关闭路径（五能力关闭、不崩溃、调用方不变）；KTextEditor 层的着色回退由
  `r2-c17-probe` 的 overlay 删除回退实验支撑（见 `evidence/r2-c17/结论.md` §2.2）。
- 许可：两个 grammar 都 MIT，未绑定 GPL；`verilog_placeholder` 自写无第三方义务。

## 8. 本次未证明 / 局限

- `verilog_placeholder` 只覆盖探测所需的 Verilog 子集（module/assign/always/begin-end/简单表达式），
  不代表生产级 Verilog 语义；生产 grammar 的选型与许可由 `r2-license` / `syn-grammars` 决定。
- 未测 grammar ABI 不匹配时的错误路径（本镜像树 tree-sitter 0.25.9 与 ABI 15 grammar 匹配）。
- 未测 query 编译失败/超时/超长文件的鲁棒性；未测 parser 取消（timeout）机制。
- 未测 tree-sitter 与 KTextEditor 主循环的线程/时序配合（该部分属于 `syn-provider`/`syn-overlay`）。
- 运行期开关是“provider 层整体关闭”，不是“逐 grammar 热插拔”；热插拔未实现也未验证。
