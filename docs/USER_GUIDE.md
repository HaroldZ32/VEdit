## 1. 安装（三种产物，选一种即可）

三种产物都**自带** GTK3 运行时、GtkSourceView 数据、verible、slang、字体与输入法模块，
不需要在目标机上安装任何软件包。

### 1.1 AppImage（最省事，需要 FUSE）

```sh
chmod +x VEdit-0.1.1-x86_64.AppImage
./VEdit-0.1.1-x86_64.AppImage
```

CentOS 7 常常没有 `fusermount3`，直接运行会以 `No suitable fusermount binary found` 退出 127。
两种兜底方式：

```sh
./VEdit-0.1.1-x86_64.AppImage --appimage-extract-and-run
APPIMAGE_EXTRACT_AND_RUN=1 ./VEdit-0.1.1-x86_64.AppImage
```

### 1.2 目录包 tar.gz（不需要 FUSE，最稳）

```sh
tar xzf vedit-0.1.1-linux-x86_64.tar.gz
./VEdit/vedit.sh                 # 空编辑器
./VEdit/vedit.sh path/to/top.sv  # 直接打开文件
```

包可以解压到任意位置（家目录、`/opt`、共享盘），启动脚本按**自身所在目录**解析所有路径。

### 1.3 单文件自解压 `.run`（不需要 FUSE，单文件）

```sh
sh VEdit-0.1.1-x86_64.run path/to/top.sv
# 或
chmod +x VEdit-0.1.1-x86_64.run && ./VEdit-0.1.1-x86_64.run
```

行为说明：

- 先尝试 `${TMPDIR:-/tmp}`，并**实际试执行**一个探针脚本；若该文件系统是 `noexec`，
  自动回退到 `${XDG_CACHE_HOME:-$HOME/.cache}/vedit/`，再试一次；
- 两者都不可执行时，以退出码 3 明确报错，并提示可用的替代方式（tar.gz / AppImage extract-and-run）；
- 退出时清理解包目录；调试时设 `VEDIT_KEEP_TMP=1` 可保留并打印路径；
- 参数原样传给编辑器（`--selftest all`、`--version` 等）。

### 1.4 从源码得到 Qt6 构建（v2 交付物）

§1.1–1.3 是**旧 GTK3 产物**的安装方式。要拿到 v2 的 Qt6 交付物，从源码构建：

```sh
bash scripts/build-qt.sh              # 固定镜像 → Rust 服务层 → configure → build → ctest → xcb 冒烟
bash scripts/build-qt.sh --no-test    # 只 configure + build
```

产物是 **`target/qt6-build/src/app/vedit-app`**（CMake 构建树在 gitignored 的 `target/qt6-build/`）。
`bash scripts/build.sh` 是**旧产品**：只产出 `target/release/vd-app`，**不产出 `vedit-app`**。

把 `vedit-app` 放到另一台机器直接跑时，需要 KF6/Qt6 运行库、`libtree-sitter0.25` 和 Qt 平台插件
（`libqxcb`）；实测包名见 `evidence/runtime-deps/REPORT.md` §1，构建期版本矩阵见 `docs/BUILD.md`
§12.3。注意构建基线是 glibc 2.43，比它老的系统（含 CentOS 7）要连 glibc 一起打包（同文件 §2）。

## 2. 第一次使用

本文同时标注 **Qt6 产品** 与 **旧 GTK3 产物** 的差异：两者的命令行选项与工程根起点不同，
请先确认手上的产物版本，再照下面的步骤操作。

1. 启动后 `Ctrl+O` 打开一个 `.sv`/`.v` 文件，或直接把文件路径作为参数；
2. 底部状态栏依次显示：光标位置、文件路径、语言（`systemverilog`/`verilog`）、
   verible 诊断数、slang 诊断数、FIM 状态、LSP 进程状态；
3. 打开工程：先确认手上是哪一版——**Qt6 构建** → 启动时用 `--project <dir>` 指定工程目录
   （或恢复上次会话）；**旧 GTK3 产物** → 该版本不认识 `--project`，会以
   `unknown option '--project'` 在 GUI 启动前直接退出（`crates/vd-app/src/cli.rs:101`；
   解析发生在 GUI 之前，`crates/vd-app/src/main.rs:25`），请先 `cd` 到工程目录再启动。
   工程根**从起点目录向上逐级查找**：在每一级依次看 `vedit.toml`（优先）→ `.git` → 该目录是否
   **直接包含 `*.f`**，命中的第一级即工程根（来源依次报告为 `vedit_toml` / `git_dir` /
   `filelist`，都没命中的退化为起始目录 `fallback`）；起点目录的定义见本节末
   （Qt6 = `--project` 目录，旧 GTK3 = 进程启动目录）。
   所以一个只带 `project.f` 的目录本身也算工程根，即使它位于更大的 git 仓库内部：以该目录为
   起点时根就是它自己（`filelist`），而以它所在的外层仓库为起点时根仍是外层（`git_dir`），
   嵌套的 `.f` 不会把根改到子目录；同一目录同时有 `.git` 与 `*.f` 时根不变，来源按更强的
   `.git` 报 `git_dir`。扩展名大小写不敏感：`.F` 与 `.f` 同样算根
   （`has_f_extension` 用 `eq_ignore_ascii_case("f")`）。在此之上的 `.rules.verible_lint` 与
   `*.f` filelist 会被自动发现；
4. 语法高亮是自动的（按扩展名），主题默认 `cobalt`，可在 `[ui] theme` 改。支持的语言与扩展名见
   下面「语法高亮」小节。

### 语法高亮（按扩展名，Qt6 产品）

打开文件时按**扩展名**选定义，映射表**先查表、表里没有才问编辑器仓库**（所以装了 KDE 的机器上
`.v` 也不会被 KDE 的 `V`/vlang 定义抢走）。随包定义（`resources/syntax/`，全部 LGPL-2.1-or-later）
覆盖：

| 扩展名 | 定义名 | 说明 |
|---|---|---|
| `.v` `.vh` `.vlg` | `Verilog` | |
| `.sv` `.svh` | `SystemVerilog` | 含模块/接口/类/函数/任务/`generate` 的折叠区 |
| `.vhd` `.vhdl` | `VHDL` | VHDL-2008 关键字；大小写不敏感；`entity`/`architecture`/`process`（含 `p1: process` 这类带标签形式）/`block`/`function`/`procedure` 等可折叠 |
| `.md` `.markdown` `.mdown` `.mkd` | `Markdown` | 标题、围栏代码块、行内代码、强调、链接、引用、列表 |
| `.tcl` `.tk` | `Tcl` | Tcl 8.6 命令集 + Tk 控件命令 |
| `.sdc` `.xdc` | `Tcl` | **用户裁定**：SDC/XDC 就是 Tcl；这两种扩展名没有独立定义文件，由映射表指到 `Tcl`，并额外高亮 SDC 约束命令（`create_clock`、`set_input_delay`、`set_false_path`、`create_generated_clock` …） |

要点：

- 扩展名**大小写不敏感**（`TOP.V`、`Timing.SDC` 同样命中）。
- 映射表里没有的扩展名仍会回退到编辑器仓库能认出的**任意合法定义**（不再限定作者）——
  例如 `.py`、`.cpp` 在装了 KDE 定义的开发机上仍有颜色；两者都没有时才以纯文本显示。
- 语法定义**随包**：打包形态下启动脚本把 `XDG_DATA_DIRS`/`XDG_DATA_HOME` 收窄到 AppDir，
  所以机器上装没装 KDE 都不影响；AppDir 里固定的落点是
  `usr/share/org.kde.syntax-highlighting/syntax/`。
- 折叠由 KSyntaxHighlighting 定义计算，**打开文件时不自动折叠**（与 VS Code/Kate 一致）：
  点 gutter 上的折叠标记展开/收起。
- 主题只改配色，不改上面这张表；自定义定义可放到
  `$HOME/.local/share/org.kde.syntax-highlighting/syntax/`（开发/自编译运行时生效，
  AppImage/包内运行时被收窄的 XDG 路径隔离，属已知边界）。

工程根的**起点**在两个前端不同：旧 GTK3 前端（`crates/vd-app`）以**进程启动目录**
（`std::env::current_dir()`）为起点；Qt6 产品有三条来源，优先级如下：

1. `--project <dir>`（写入 `ShellOptions.projectRoot`）；
2. 恢复的会话里上次的工程根；
3. **打开一个 `.f` / `.F` / `.flist` filelist**：当前没有工程时，以该 filelist 所在目录为工程根
   （`crates/vd-config` 的 `RootSource::Filelist`），然后把它导入工程；已有工程时只把它导入
   **当前**工程根，**不切换工程**（切换会清掉已经导入的 filelist）。实现是应用层一个与 lane
   无关的 `ApplicationShell::fileOpened` 信号 + 工程 lane 自己决定扩展名含义
   （`src/workspace/project/project_filelist.cpp`），`src/app` 不依赖工程 lane。
   `File → Open`（`Ctrl+O`）的过滤器也列出了 `*.f *.F *.flist`。

打开普通源文件（`.v` / `.sv` / `.svh` / `.vh`）**不会**推导或切换工程根；GTK3 前端仍只以
进程启动目录为起点。`crates/vd-config` 的 `Loader::new(start_dir)` 接口约定调用方传被打开文件
所在目录（`crates/vd-config/src/lib.rs:93-103`），Qt6 传的是 `--project` 目录或 filelist 目录，
GTK3 传的是进程启动目录。因此 Qt6 里也可用 `--project` 指定工程目录（根发现从该目录向上）；
旧 GTK3 前端要先 `cd` 到期望的工程目录再启动。

编辑能力：多标签（`Ctrl+N` 新建、`Ctrl+W` 关闭、未保存会确认）、原生撤销/重做、
查找/替换/下一个（`Ctrl+F`/`Ctrl+H`/`F3`）、跳行（`Ctrl+G`）、CRLF 保留、原子保存
（写临时文件再 rename，避免半截文件）。

### 打开另一个文件夹（`File → Open Folder…`）

Qt6 产品里，`File → Open Folder…` 会在**运行时**切换工程根，不需要重启：

- 选中的目录成为新的工程根，**文件树、搜索、VCS 面板、模块树**四个面板都跟着切到新根
  （文件树重新列出新根、搜索只在新根里查、VCS 表头显示新根的仓库/分支、模块树重新展开）；
- 原本打开的标签页**不会关闭**；它们的路径保留，只有"工程范围"相关的面板换根；
- 新根会写进会话文件，**正常退出再启动时自动恢复**（与 `--project <dir>` 等价，只是不用重启）；
- 选中一个不是工程根的目录也可以：工程根仍按本文的规则（`vedit.toml` → `.git` → 直接含 `*.f`）
  向上查找，找不到就退化为该目录本身。

对应的自动化证据：`docs/ACCEPTANCE-MATRIX.md` 的 AC-1.2 行（真实 shell probe 记录三处状态变化）。

### 路径显示（统一规则）

Qt6 产品里，**下列界面**显示路径时用同一条规则（`src/common/path_display.h`）：

- 工程根存在且文件在根内 → 显示相对工程根的路径（不带 `./`）；
- 否则 → 显示绝对路径。

覆盖编辑器标签的 tooltip、窗口标题、Files 树的 tooltip、Project 面板的文件与 filelist 列表、
`Ctrl+P` 文件面板和搜索结果行。**打开和去重仍用绝对路径**，显示规则不改变任何打开行为；
工程根会先规范化（绝对路径、去掉 `.` / `..` / 尾斜杠）再参与比较。编辑器标签文字本身显示文件名
（不是路径），tooltip 才显示上面这条规则算出的路径。

**状态栏 / 面板的一次性确认与错误提示是例外**：palette / Files 树 / 搜索跳转的 `Opened …`、
Project 面板的 `Removed …` 和错误提示仍显示绝对路径（只停留几秒，不是路径视图）。除上面枚举的
界面和这些一次性提示外，如果看到绝对路径显示，就是 bug。

### 文件列表（`.f`）里的变量与转义

在 Qt6 产品里，打开一个 `.f` / `.F` / `.flist` 会**同时**把它作为工程 filelist 导入（规则见上文
"工程根的起点"）；filelist 也仍然作为普通文本标签打开。**编辑后要按 Project 面板的 `Refresh`
重新展开**（重新打开同一个 filelist 不会重新解析），重复打开同一个 filelist 是幂等的：不会重复
加入，也不会重复解析，Project 面板底部会提示 `Already imported: nothing changed`。解析诊断（缺失的 `+incdir+`、未知 token、
嵌套 `-f` 问题等）显示在 Project 面板的诊断列表里，不会弹出模态框。

`.f` 的**每一行**（文件路径、`+incdir+`、`+define+`、`-f` 的参数都算）先做变量展开，再按指令解释：

| 写法 | 含义 | 例子 |
|---|---|---|
| `$NAME` | 变量；名字以字母或 `_` 开头，后面是字母/数字/`_` | `$RTL/a.sv` |
| `${NAME}` | 同上，用花括号划界（后面紧跟字母或数字时必须用它断开） | `${RTL}_tb.sv` |
| `$(NAME)` | 同上，用圆括号划界（`Makefile` 风格） | `$(RTL)/a.sv` |
| `$$` | **一个字面 `$`**（唯一的转义写法，不展开） | `out_dollar$$.sv` → `out_dollar$.sv` |
| `~/…` | 当前用户的 `HOME`；只在行首或分隔符（空白、`+`、`=`）之后、且紧跟 `/`（或就在行尾）时展开。`~user` **不做**用户查询，按字面保留 | `~/gen/a.sv` |

**不构成上面任何一种引用时，`$` 就是字面 `$`**（shell 规则）：`out_dollar$.sv`、`out_tail.sv$`
都是合法路径，不会被当成“写坏了的变量”而丢掉。只有 `${` / `$(` 开了头却没闭合、或 `${}` / `$()`
名字为空，才算语法错误（该行报 `file:line` 并跳过）。

**优先级：工程变量表 > 系统环境变量。**工程变量表在工程面板的 **Edit Variables…** 按钮里逐行填
`NAME=VALUE`（首次展开发现未解析变量时，面板也会自动弹出同一个对话框），保存后写进
`project-model.json`，重启仍在。例：工程表 `PREC=project`、环境 `PREC=environment`，
`+define+PREC=$PREC` 得到 `PREC=project`；删掉工程表那一行才轮到 `environment`。`HOME` 始终来自环境。

**没有变量或路径是悄悄丢掉的**（每条都带 `.f` 路径和 1-based 行号）：

- **变量未解析**（工程表和环境里都没有）：该行跳过并给一条 `config.invalid_value` 诊断；所有未解析
  的名字会被收集成一批，用一个对话框一次填完，取消对话框不会丢掉已导入的结果，这些行会留在诊断里。
- **展开后的路径不存在**：条目**保留**（生成文件稍后出现时仍然生效），同时给一条 `filelist.missing`
  诊断，写清**实际查找的路径**和原因；行首 `~` 不是 `~/` 时同样按字面保留并报告。
- **嵌套 `-f`** 的路径按**包含它的那个 `.f` 所在目录**解析；环形引用会点名整条链
  （`a.f -> b.f -> a.f`）；嵌套深度上限 16 层，超限的诊断会点名被跳过的那个文件。
- 不认识的 `+…`/`-…` 指令报一条诊断后跳过，不会让工程打不开。

注意：目录扫描只认 `v`/`sv`/`vh`/`svh` 扩展名，所以像 `out_tail.sv$` 这种“扩展名被 `$` 打乱”的名字
通常只能通过 `.f` 进入工程——这也是上面“保留并报告”两条规则重要的原因。

## 3. Verible 在线能力（默认快捷键见下表）

打开工程后，`verible-verilog-ls` 由编辑器自动拉起（状态栏显示 `LSP running`）：

下表按 **Qt6 产品（`vedit-app`）** 的默认快捷键列出；旧 GTK3 产物有两处不同，已在「说明」里注明。

| 能力 | 操作 | 说明 |
|---|---|---|
| 实时诊断 | 自动 | 问题面板 + 行号栏标记（error/warning/note），点击行跳到对应位置 |
| 一键格式化 | `Ctrl+Shift+F` | 执行**外部** `verible-verilog-format`（不是 LSP 的 documentFormatting），**一次撤销**即可回退 |
| 跳转定义 | `F12` | 跨文件 |
| 查找引用 | `Shift+F12` | 结果列表 |
| 符号大纲 | `Ctrl+Alt+O` | 切换大纲面板，显示当前文件的符号（旧 GTK3 产物是 `Ctrl+Shift+O`） |
| 重命名符号 | `F2` | Qt6 **会应用**编辑；旧 GTK3 产物只预览、不写文件 |

表中除「一键格式化」外，实时诊断、跳转定义、查找引用、符号大纲与重命名都由 `verible-verilog-ls`（LSP）提供；
**一键格式化不走 LSP**——Qt6 直接调用随包的 `verible-verilog-format` 外部进程，没有 `documentFormatting` 请求。

LSP 异常退出时会提示并可重启后端；LSP 请求不阻塞 UI。

## 4. SLANG 深度 lint

- 旧 GTK3 产物默认 `Ctrl+Shift+L`；Qt6 产品里 slang 是工程 lint 的默认引擎（菜单 / 工具栏「检查工程」，
  没有独立快捷键，见 §13.2 / §15.3）。两者执行的都是 `slang --lint-only -Weverything --diag-json <file>`；
- 结果显示在问题面板（severity / message / code / 文件:行:列，行列按 1 基显示）；
- 触发期间 UI 可交互；重复触发会取消上一次的结果；
- slang 缺失/损坏/返回非法 JSON/非 0 退出码时：状态栏给错误提示，编辑器继续可用、不崩溃；
- `slang` 的路径解析顺序：`VEDIT_SLANG` → 包内相对路径（`bin/slang`、`../lib/vedit/bin/slang`…），
  **不查 PATH**。

## 5. 可选 FIM 补全

**默认关闭**：未配置时不会发出任何网络请求、不弹错误框、不拖慢启动；编辑/保存/跳转全链路正常。

配置（用户配置 `~/.config/vedit/vedit.toml` 或工程 `vedit.toml`）：

```toml
[fim]
enabled = true
protocol = "open_ai"     # OpenAI 兼容 /v1/completions（prompt + suffix）
                         # 或 "llama_cpp"（/infill，input_prefix + input_suffix）
endpoint = "http://127.0.0.1:8080"
model = "qwen2.5-coder"  # llama_cpp 不需要
timeout_ms = 5000
# api_key 可写在这里，或用环境变量（推荐后者）
```

等价的环变量：`VEDIT_FIM_ENABLED`、`VEDIT_FIM_PROTOCOL`、`VEDIT_FIM_ENDPOINT`、
`VEDIT_FIM_MODEL`、`VEDIT_FIM_TIMEOUT_MS`、`VEDIT_FIM_API_KEY`（环境变量优先级最高）。

使用：`Alt+\` 请求补全 → ghost text 显示 → `Tab` 接受 / `Esc` 取消 / 继续输入自动作废。
失败（超时、401/500、连不上）只在**状态栏**显示一句短提示（如 `FIM HTTP 401`），不阻塞编辑。

### 安全边界（请务必读）

- **密钥来源**：环境变量 `VEDIT_FIM_API_KEY` 优先；也可以写在 `vedit.toml` 的 `[fim] api_key`（工程或
  用户配置）。设置页**从不**把密钥写进 `settings.toml`——它写入与 `settings.toml` 同目录、属主 0600 的
  `fim_api_key`；界面只显示密钥来源，不回显密钥；没有内置默认端点/模型/密钥；
- 密钥在类型层面被 `ApiKey` 包裹：`Debug`/`Serialize` 恒为 `<redacted>`，**没有 `Display`**，
  明文只能在发请求的一处读出；日志、错误、状态栏都不含密钥；
- 请求错误只暴露状态码/超时值/固定类别，**不含请求头、key、带 query 的完整 URL**；
- 响应体积上限 64 KiB，超出即失败；请求由 `timeout_ms` 兜底；
- **取消是结果级**：网络 I/O 不会中途 abort，迟到的响应会被丢弃（陈旧结果永远不会覆盖新结果）；
- 默认关闭时**连传输层都不构造、线程也不创建**，这是一条结构性保证（有自动化测试与证据）。

### 密钥的存放（设置界面 / 用户级 0600 文件）

在 **Settings → Preferences…（Ctrl+,）→ FIM 页** 填写的密钥不会写进 `settings.toml`，也不会出现在日志或界面回显里：

- **优先级**：环境变量 `VEDIT_FIM_API_KEY` 始终最高；设置页保存的密钥位于与 `settings.toml` **同目录**的
  `fim_api_key`（属主 0600）；
- 该文件只允许属主读写（0600），并且是**创建时即 0600**（不是先创建再改权限），采用临时文件 +
  原子替换写入；权限不对（例如 0644）的文件会被**忽略**，界面会提示你 `chmod 600` 修复，而不是照读；
- 设置页的密钥输入框是**只写**的：已保存的密钥永远不会回填到界面；界面只报告密钥来源
  （环境变量 / 用户级文件 / 无）以及文件是否权限过宽；
- 手工把 `"fim.api_key" = "..."` 写进 `settings.toml` 会被忽略，并在下一次保存时被清除（不带引号的
  `fim.api_key = ...` 会被 TOML 当成嵌套表，同样进不了扁平设置存储）；
- 已知残留：如果进程在“创建临时文件”与“原子替换”之间被强制终止或断电，同目录可能留下一个 0600 的
  临时文件（**含密钥，但仅属主可读**）；下一次保存密钥时会清理这类陈旧临时文件。

## 8. 排障

| 现象 | 原因 / 处理 |
|---|---|
| AppImage 报 `No suitable fusermount binary found`（exit 127） | 没有 FUSE：用 `--appimage-extract-and-run`，或改用 `.run` / tar.gz |
| `.run` 报 "no extraction directory allows executing files" | `/tmp` 与 `$HOME/.cache` 都是 `noexec`：设 `TMPDIR` 指向可执行目录，或改用 tar.gz |
| 打开文件但**没有语法高亮** | GtkSourceView 数据目录不在搜索路径。用包内启动方式运行；tar.gz / `.run` 可用 `VEDIT_PRINT_ENV=1 ./VEdit/vedit.sh` 打印启动环境自查（AppImage 的 AppRun 无此开关） |
| 状态栏提示 verible/slang 找不到 | 用包内启动脚本；或设 `VEDIT_VERIBLE_DIR` / `VEDIT_SLANG` 指向实际路径（**不会查 PATH**） |
| 状态栏一直 `FIM 未启用` | 这是默认行为；要启用见第 5 节 |
| 中文显示成方块 | 用了非包内启动方式导致字体目录未生效；用包内 `vedit.sh`/`.run`/AppImage |
| 输入法无候选框 | 系统未装/未运行 ibus/fcitx；VEdit 只提供 GTK 侧模块 |
| 启动日志 `Locale not supported by C library` | 目标机缺 `en_US.UTF-8` locale；不影响显示，可 `localedef` 生成 |
| 界面语言选“自动”后仍然是英文 | “自动”跟随系统 locale；打包运行时 AppRun 把 `LANG`/`LC_ALL` 固定为 `C.UTF-8`（包内只带 C.utf8），Auto 因而解析为英文。在 Preferences 里显式选“简体中文”并重启即可；若自行提供中文 locale，Auto 会跟随它 |
| 无头容器里 `--screenshot` 得到空白图 | 已知问题（无窗口管理器时 GTK 绘制时机）；用 X server 捕获代替 |
| 想确认安装完整性 | `sh VEdit-0.1.1-x86_64.run --selftest all`（退出码 0 即 6 套件 62 项全过） |

## 10. 版本控制（VCS）面板

Qt6 产品自带一个 SourceGit 风格的三栏 VCS 面板（左：分支/标签，中：变更/暂存，右：diff），
另有一个**历史**标签页（提交列表 / 提交详情 / 单文件历史 / blame / 两次提交比较）和一个
**工作区**对话框（stash、worktree）。

### 10.1 随包工具链（不用装 git / svn）

交付的 AppDir/AppImage 里**捆绑**了 `git 2.53.0` 与 `subversion 1.14.5`（在 `usr/lib/vcs/` 下，
含其依赖库），解析顺序是 **bundled > PATH > env**，所以干净机器上不需要另装。启动时面板/日志会打印
一行可观测的解析结果：

```
VCS-TOOLCHAIN git=… version=2.53.0 svn=… version=1.14.5 source=bundled
```

想强制用系统自带的版本，可以设 `VEDIT_GIT` / `VEDIT_SVN`（或对应的 `_DIR`）指向自己的二进制；
`svnadmin` **不随包**（只在构建期造 E2E fixture 用）。

### 10.2 能做什么

- 读：状态（backend / 分支或修订 / 变更文件）、单文件 diff、refs、提交历史、blame、比较；
- Git 写：stage/unstage/discard、commit（含 amend）、fetch/pull/push（`file://` 或本地裸仓库）、
  分支与标签的创建/切换/删除/重命名、merge/rebase/cherry-pick/revert/reset、stash、worktree、submodule；
- SVN：status/info/diff/commit/update/revert/add/remove，能力表里不支持的操作会在面板置灰并给出**真实原因**
  （不是"未实现"）。

### 10.3 安全边界（请务必读）

- **读路径拒绝一切写子命令**：读 runner 在**启动进程之前**就拒绝 commit/push/checkout/reset/revert/switch/update 等；
  写只能走**逐操作白名单**（9 个类型化操作），未列出的操作码、非仓库、后端不匹配、越界路径一律默认拒绝。
- **危险操作要确认两次**：`reset --hard`、`clean`、`discard`、删除分支/标签、删远端、`worktree remove`
  都是「确认 → 再确认」，任一步取消都**不写任何东西**。
- **凭据不落盘**：没有 helper/SSH 时弹出的凭据框只把密码放进**子进程的环境变量**，不进 argv、不写文件、
  不进日志或证据；取消即中止，并显示 git 的真实原因。
- 所有 VCS 操作都是**异步 job**（轮询式），即使 `git`/`svn` 卡住，界面也不会冻结。

### 10.4 没有承诺的东西

真实网络传输（HTTPS / SSH 远端）**没有**做端到端验证：证据只覆盖本地裸仓库（`file://`）与一个本地
401 认证传输。历史列表有上限（一次一页 ≤ 200 条、blame ≤ 20000 行、文本 ≤ 2 MiB、refs ≤ 2000）。

## 11. 模块树与接口面板

> **适用范围**：§11–§15 只适用于 **Qt6 产品（`vedit-app`）**。§1.1–1.3 的旧 GTK3 产物没有这些面板与设置页。

Qt6 产品在**右侧停靠区**提供两个联动面板：**模块树**与**接口**。两者的数据都来自 slang 对**整个工程**做的
一次模块目录（module catalog），异步执行，不会卡住编辑。打开方式：`View` 菜单里的面板开关（模块树 / 接口）。

### 11.1 模块树：只有模块，没有网络/驱动/负载

- **根节点 = 从未被例化的模块**（顶层模块），可以有一个或多个。"定义了但没有任何地方例化"的模块也会作为根出现。
- 同一个模块被两个父模块例化时，它在**两个父下各出现一行**（靠缩进区分实例路径）；`例化次数` 列是该父下例化的个数。
- 列：**模块 / 例化次数 / 定义位置**。旧版本的"网络 / 驱动 / 负载"行已**彻底删除**——树里只有模块。
- **双击模块行** → 打开它的定义文件，并把光标定位到 `module` 声明处。
- 工具栏：**刷新**（对整个工程重新跑一次模块目录）、**过滤模块…**（不区分大小写，匹配模块 / 例化次数 /
  定义位置任一列；匹配行的父行始终保留可见，过滤只隐藏不重建）。
- 保护：层级深度上限 64 层、最多 20000 行；超限或环形例化会显示一行标记，不会崩。
- 底部汇总行给出 `slang`、模块数、顶层数、本次目录耗时与峰值内存；有告警时在**同一行末尾**追加 ` · ⚠ …`。
- 空态：没有工程或 slang 没报出模块时只显示一行原因（如"未找到模块：slang 未报告此工程的任何模块定义。"），
  不会把每个文件渲染成错误。

### 11.2 接口面板：跟随焦点模块

- 列：**名称 / 方向 / 类型 / 位宽 / 位置**。
  - 方向：`In` / `Out` / `InOut`；`ref` 端口显示 `Ref`；
  - 类型：声明里的原样字符串（如 `logic[3:0]`）；
  - 位宽：从类型字符串推导——`logic[3:0]` → 4，没有打包维度 → 1；无法解析时留空，tooltip 说明原因；
  - 位置：端口声明处的 `文件:行:列`。
- 焦点规则：模块树里**选中了模块**就用它；否则用**编辑器光标所在的模块**（同文件内"定义行 ≤ 光标行"的最近一个模块）。
  切换编辑器 / 分屏、改变选中、重新展开，都会刷新。
- **双击端口行** → 跳到该端口的**声明处**。
- **Ctrl+双击端口行** → 跳到**该模块被例化的那条语句**（父模块里 `u_xxx` 那一行）；有多个父模块时先弹选择列表，
  每项标出"父模块 · 实例路径 · 文件:行"。
  诚实说明：模块目录里**没有**"端口连接位置"的信息，所以跳的是**例化语句**，不是具体连线——面板 tooltip 也这么写。
- 空态：没有焦点模块时显示"没有焦点模块——请在模块树中选择一个模块，或将光标置于模块定义内。"

## 12. 搜索与替换

两个搜索入口，**选项语义一致**：

| 入口 | 打开方式 | 能搜的范围 |
|---|---|---|
| 编辑器查找浮条 | `Ctrl+F`（带替换框的 `Ctrl+H`） | 当前文件；也可以把查询交给搜索面板 |
| 搜索面板（Search） | `View → 切换搜索面板`（`Ctrl+Alt+S`），或工具栏的搜索按钮（菜单里的 `View → 在文件中搜索`；打开面板并聚焦输入框） | 当前文件 / 整个工程 |

### 12.1 共享选项

两个界面都提供同一组选项：**区分大小写 / 全词匹配 / 正则表达式 / 范围（当前文件 | 整个工程）**，语义一致。
搜索面板还多一个 **Verilog** 过滤器：只搜 `.v/.vh/.sv/.svh`（按显式扩展名表）。

### 12.2 搜索

- 输入查询词后按**搜索**；搜索**异步**执行，随时可以**取消**。
- 结果按 **文件 / 行 / 匹配** 三列列出，双击一行跳到命中处。
- 结果有上限：默认 **2000 条命中**与 **15 秒时间预算**；达到任一条会在结果里注明"结果不完整"，需要缩小查询。
- 空态会说明原因（无工程、未输入查询、无当前文件等），并给出一行下一步。

### 12.3 替换：两个按钮，先保存后写盘

- **替换**：只替换**当前选中的那一条**，然后跳到下一条。
- **全部替换**：先弹确认框，写明"将 X 替换为 Y？将替换 N 个文件中的 M 处"；确认后按文件分组写入，
  **每个文件一次原子写**（临时文件 → 重命名），完成后报告替换计数并刷新结果。
- **先保存后替换**：命中的文件如果正在编辑器里且有未保存修改，替换前会**先保存**（结果里会报告保存了哪些文档）；
  保存失败则整次替换被拒绝，不写任何东西。
- **会在写之前拒绝、并要求重新搜索的情况**（每条都会显示原因）：
  - 文件在搜索 / 计数扫描期间被写入（mtime 变化）；
  - 命中行在替换前的文本已和搜索时读到的不一致（逐命中行指纹校验）；如果命中的文件是**未保存的缓冲区**，
    替换前还会把**缓冲区里的整行**与**磁盘上的整行**做一次完整比对（去 BOM + trim，与写入端同一个解码/切分），
    不一致就拒绝，不保存、不写入；
  - 查询词或选项在扫描期间被改动；
  - 结果达到上限或时间预算，命中列表不完整；
  - 编辑器桥不可用，无法确认未保存缓冲区的状态；宿主不提供 `bufferText()` 且命中行超过 400 字符预览时，
    直接拒绝（不保存、不写入）。
- 上述校验无法覆盖的**最窄残留边界**见 §16 第 4 条。

### 12.4 正则：工程级是 RE2 风格

- **当前文件**（`Ctrl+F` 浮条）：Qt `QRegularExpression`，PCRE 风格——反向引用 `\1`、lookaround `(?=…)`/`(?<=…)` 等可用。
- **整个工程**（搜索面板）：Rust `regex` 引擎，**RE2 风格**——**不支持**反向引用和 lookaround；字符类、量词、分组、
  `^`/`$`、`\b` 等常见语法照常。
- 同一个正则在两个范围里**结果可能不同**；工程级搜索建议先用简单模式验证，再加复杂断言。

### 12.5 `Ctrl+F` 浮条与全工程

- 浮条的范围选择器有 **当前文件 / 整个工程**。
- 选**整个工程**时，浮条把**查询词与选项**交给搜索面板（状态行显示"整个工程 → 搜索面板"），由面板执行搜索；
  浮条自己不再假装能在单文件里搜全工程。
- 全工程**替换**只能在搜索面板里做（浮条会提示"整个工程的替换在搜索面板中执行"）。

## 13. 诊断：自动 lint、悬浮修复与文件状态点

### 13.1 两个诊断来源与优先级

- **上位 = 工程 LINT**：`project.lint` 对整个工程跑一趟批量 pass，覆盖范围内的所有文件。
- **下位 = 文件级 / LSP LINT**：语言服务器推来的逐文件诊断，或单文件 lint。

同一个文件在某一轮里有上位结果时，**编辑区只显示上位结果**（不叠加、不去重合并出双份）。
文件在上位 pass **之后被编辑** → 该文件的**上位结论立即作废**，回落到下位，直到下一次工程 lint。
这条规则对**所有**呈现生效：编辑区波浪线、gutter、诊断面板、悬浮框、文件树状态点，以及任何计数（只有一个来源）。

### 13.2 保存后自动跑工程 lint（静默）

- **每次保存成功后自动触发**一次**工程** lint，包括另存为与全部保存。
- **先落盘再 lint**：不会阻塞或推迟保存本身。
- **去抖 700 ms**：连续快速保存合并成一次；**单飞**：上一轮还在跑就取消并重启最新一轮，不排队堆积。
- 自动跑的结论只进编辑区显示、文件树状态点、诊断面板、状态栏；**绝不弹模态框**。

### 13.3 显式 Lint Project 与 ELAB 引导

- 菜单 / 工具栏的**检查工程（Lint Project）**是**显式**触发。
- ELAB 失败（工程级错误）时：**显式**触发才弹模态框「工程 lint 错误」，列出错误，**双击一条跳到它**；
  自动跑只给**可点击的状态栏提示**"⚠ N 个工程错误——点击跳转"，点一次跳下一个。

### 13.4 悬浮框与「修复」按钮

- 鼠标停在诊断波浪线上 → 弹出**严重级 + 规则 id + 消息**。
- **引擎确实能修**这条规则时才出现**修复**按钮：它在**临时副本**上跑 verible `--autofix`，再对当前文档做
  **一次可撤销的整文替换**（一次撤销即可还原），成功后状态栏提示"已用 verible-verilog-lint 修复 N（一次撤销即可还原）"。
- 引擎不能修 → **不给按钮**，原因写在 tooltip 里（例如"未找到 verible-verilog-lint：无法自动修复"）。不假装能修。
- 普通符号的悬停仍走既有 LSP hover：verible 不 advertise `hoverProvider`，但请求**实际有内容**，
  所以这里不按"不支持"置灰。

### 13.5 文件树状态点

文件树在**图标与文件名之间**画一个状态点，数据取自 §13.1 的合并视图，随刷新更新（不会每帧重扫全工程）：

| 颜色 | 含义 |
|---|---|
| 红 | 该文件有 **error** |
| 黄 | 只有 **warning**（没有 error） |
| 绿 | **干净**（有结论且没有问题） |
| 无点 | 没有结论：目录，或还没有被任何一轮 lint 覆盖到的文件 |

### 13.6 Rename（重命名符号）

- 光标必须落在**可改名的符号**上；不在符号上时**先给出原因**（"重命名需要光标位于符号上（第 X 行第 Y 列没有符号）"），
  **不会先让你输入新名字再失败**。
- 后端不提供 rename 能力时：菜单 / 右键项**置灰并说明原因**，请求路径也会拒绝——不是只有界面灰。
- 重命名结果会应用到**打开的文档**，未打开的文件经**原子保存**写入磁盘；完成后报告"N 个文件共 M 处编辑"。
- **不承诺跨文件**：verible 的 LSP 会话是文件作用域，只对当前打开文件作答（见 §16 第 2 条）。

## 14. 代码导航与多光标

| 手势 | 作用 |
|---|---|
| `Ctrl+左键` | **跳转到定义**：先把光标放到点击处，再走与 `F12` **同一条**派发路径 |
| `Alt+左键` | **加光标**；点到已有光标上则移除该光标 |
| `Alt+拖拽` | **块选择**（矩形选区，每行一个光标） |
| 普通点击 / 拖拽 | 与以前一样 |

- 后端不提供定义能力时：`Ctrl+点击` **按普通点击处理**，并在状态栏说明一次原因
  （"此处无法转到定义：…——Ctrl+click 现在与普通单击相同"），不会静默吞掉。
- **点哪个分屏就激活哪个分屏**：鼠标按在非活动分屏的**任意位置**（包括编辑器内部的真实控件）或焦点进入该分屏，
  都会把它设为活动分屏；之后的命令、工具栏动作、跳转与重命名都跟随活动分屏。
- 下方的快捷键与 **Qt6 的命令注册表**一致（旧 GTK3 产物在符号大纲 / 重命名两项上不同）：

| 命令 | Qt6 默认快捷键 | 说明 |
|---|---|---|
| 跳转到定义 | `F12` | 与 `Ctrl+左键` 走同一条派发路径 |
| 查找引用 | `Shift+F12` | 结果列表 |
| 符号大纲 | `Ctrl+Alt+O` | 切换大纲面板（旧 GTK3 是 `Ctrl+Shift+O`） |
| 重命名符号 | `F2` | **会应用**编辑，不是预览 |
| 格式化文档 | `Ctrl+Shift+F` | 一次撤销可回退 |

## 15. 设置：字体、缩放、Format 与 Lint

打开：`Edit → 首选项…`（`Ctrl+,`）。页签：**快捷键 / 工具 / FIM / 界面 / Lint / 格式化**。

### 15.1 界面：字体与缩放

- **字体大小**：立即作用于整个界面（`QApplication` 字体），不需要重启；选**跟随系统**表示**不保存任何值**。
  编辑器自身的字体是 KTextEditor 的设置，不在这里改。
- **界面缩放**：`100% / 125% / 150% / 200%`。Qt 只在应用构造时读一次 `QT_SCALE_FACTOR`，所以**下次启动**才生效；
  页面会提示"重启 VEdit 生效"。选 `100%` 不设置任何环境变量。

### 15.2 格式化（Format）

- 23 个可配旋钮（缩进空格、列宽、wrap 空格、`try_wrap_long_lines`、各种 alignment、行终止符……）；
  高级参数收在可折叠的**高级选项**里；**恢复默认**回到 verible 的默认值。
- **默认值不发送任何 flag**：只有你改过的选项才会变成 `verible-verilog-format` 的 argv；全默认时只把输入文件
  交给格式化器，行为就是 verible 自己的默认。
- 编辑器里的 `Ctrl+Shift+F`（与菜单 `Project → 格式化文档` 是同一个命令）执行一键格式化；格式化结果**一次撤销**即可回退。

### 15.3 Lint：一个页面，两套配置

- `Lint` 页只有**一套控件**，显示**当前 Lint 引擎**（`工具 → Lint 引擎`）的那一组选项；两个引擎各自保存自己的
  设置（`lint.verible.*` 与 `lint.slang.*`），**切换引擎不丢另一套**。
- 当前引擎**不支持**的旋钮 → **置灰**，tooltip 说明原因（例如 slang 没有 `.rules.verible_lint`、waiver、autofix；
  verible 没有 `-W`、`--error-limit`）。不会静默发一个无效参数。
- 当前引擎**支持**的旋钮都会真正生效：verible 的 `--ruleset`、`--rules`、`--rules_config`、`--waiver_files`
  与 slang 的 `-W…`、`--error-limit` 都进入工程 lint 任务的 argv；默认值不发送任何 flag。
  唯一例外是 verible 的 `--autofix`：值会保存，但页面顶部的状态行写明
  **「--autofix 仅保存（Lint 任务的 C ABI 没有对应字段）」**，不会以静默无效参数发出。
- 规则文件的优先级：页面的「规则文件（--rules_config）」→ 工具页的旧 Verible rules 字段 → 工程里自动发现的
  `.rules.verible_lint` → 都没有则不传 `--rules_config`（用 verible 默认规则）。手填值优先于自动发现。

## 16. 已知限制

本节是本批次功能**诚实的边界**。VCS 面板自身的边界见 §10.4，不在本节重复。

1. **没有真机 GUI 验收**：本批次所有 GUI 证据来自 offscreen 或 Xvfb（软件渲染）截图，没有在真实桌面上
   用鼠标逐项验收；**观感、DPI、字体由你在真机上验收**。另外 Xvfb 镜像里缺 CJK UI 字体，
   证据截图里的「修复」按钮会渲染成豆腐块——按钮存在且位置正确，字形不代表产品表现。
2. **跨文件 Rename 不声明支持**：verible 的 LSP 会话是**文件作用域**，只对当前打开文件作答。
   重命名只承诺服务端在当前文件里返回的编辑（以及因此被写入的文件），不要指望它改遍整个工程。
3. **工程级正则 = RE2 风格**：搜索面板（整个工程）不支持反向引用与 lookaround；`Ctrl+F` 当前文件是 PCRE 风格
   （`QRegularExpression`）。同一个正则在两个范围里结果可能不同（详见 §12.4）。
4. **替换的最窄残留边界**（B2 披露；现有校验无法完全排除）：
   - 文件被外部程序改写，且**大小与 mtime 都不变**；
   - 在扫描窗口之外插入一行，它的**前 400 个字符（搜索预览的截断长度）与命中行相同、之后不同**：
     逐命中指纹比对的就是这段预览，看不出后面的差异。对**未保存的缓冲区**，替换会**在保存之前拒绝**，
     不写任何东西，并给出带文件名与行号的原因；只有**整行逐字一致**的副本仍然无法区分——但两种情况下
     被替换的文本相同，没有危害；
   - 宿主不提供 `bufferText()`（非产品桥）且命中行超过 400 字符预览时，面板**直接拒绝**替换（不保存、不写入），
     因为无法证明整行身份。
   这些边界之外，替换在写每个文件前都会用冻结快照 + 每命中行指纹 + 文件戳校验；对**未保存的缓冲区**还会
   先做**整行预保存比对**（缓冲区里的行 vs 磁盘上的行，去 BOM + trim，与写入端同一个解码/切分）。不符就拒绝
   并说明原因，不会写错字符。
